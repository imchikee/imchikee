## 1. 迁移性分析

检查了第一幕 contour-data.js 的 composeContour、motion.js 的合成与固定前景，以及 contour-head-down-v1.png、down-key-soft-v1.png、contour-patch-down-v2.png；另读 CONTOUR-PROMPTS.md / WHOLE-CONTOUR-PROMPTS.md 核对素材如何制作。没有把第一幕已工作的效果当作本轮重新验收。

| 项目 | 第一幕 | 第二幕 | 迁移判断 |
|---|---|---|---|
| 毛发风格 | 暖色手绘、较明显的画笔/轮廓短毛 | 同属暖色仓鼠，但腮胸及前肢细纹更密、光照方向和明暗不同 | 风格家族相近，不足以直接贴像素 |
| 头部/腮毛姿态 | 读竖起的书，脸下部被书、爪遮住；三张独立俯仰姿态 | 低头写字，横向前臂从腮胸前露出，笔斜穿邻近区域 | 前景深度关系不同；不能把读书腮边当写字肩根 |
| 局部补片 | 270×240同框的**重画补片**，已有正确外轮廓及相邻背景 | v26去臂区域是连续胸毛，没有独立腮臂接合；v33正确视觉过渡与原臂/影混合 | 第二幕没有同等兼容的现成补片 |
| 固定遮挡 | 原画书本、手爪及静止道具覆盖活动头部；本来就是画面前景 | 需让静止腮毛盖活动臂；复制干净胸毛不等于获得腮毛下缘 | 图层顺序可复用，覆盖内容不能替代 |
| 注册 | 原场景1316×1195；局部放回(200,490)，头部按(170,280,850,530)放回；已修轮廓随对应网格点参与动画 | 当前base合成v23/v26，活动v33局部按(+5,+4)注册；轨迹另用既有矩阵映射 | 两幕尺寸相同不等于局部坐标或姿态相同；握笔配准也不等于整片腮毛配准 |

**可迁移的方法**：原坐标局部带状选区、姿态素材先合成再动画、排除不该覆盖的部分、用原画的静止前景盖回活动层。这些是合成步骤，不会自动补出缺失的毛发形状。

**不可直接复用的素材**：第一幕的低头全图、头部补片和270×240轮廓补片。它们含另一场景的脸部轮廓、光照、背景、书本与爪。contour-head-down-v1.png是绘画裁片，不是可移植的透明腮毛；composeContour只取其部分轮廓，不是整块贴入。

**关键前提**：第一幕窄带选到的是已经重画好的“毛发→背景”关系。其50px宽、2px轻微遮罩过渡与3px框边过渡只是拼接辅助手段，毛尖本来在绘画中。第二幕要的是“腮毛→活动前臂”的内部遮挡；单靠相同遮罩不能从连续胸毛恢复这条边界。现有v33的部分脸颊内侧可作为颜色参考，但下沿连着原臂底色/阴影，不能干净分离；v23旧臂/笔仍在，v26则已去掉原分界。

## 2. 唯一最小迁移实验

源代码 experiment.js；全部在本scratch，复用现有70%场景接口，不加载上一轮失败补片或Alpha提取结果。

1. 取第二幕当前 **base** 的局部(330,700,270,240)，不使用第一幕像素。该来源与现有身体同坐标，避开旧臂素材的混合问题。
2. 移用composeContour的局部选择步骤：50px宽折线带，圆端/圆接，遮罩blur(2px)，内缩框(6,6,258,228)配blur(3px)。只把选区位置改到当前肩臂缝；没有扫描宽度、调参或试其他位置。
3. 像第一幕排除帽子、胡须和书本区域一样，排除第二幕已有gripWorld，保护原爪和笔。
4. 用motion.js“原画静止前景盖回活动层”的顺序，将这份**原坐标base带状像素**固定叠在现有活动臂上，再保留既有shoulderCover。手爪、笔、笔迹、armPath及形变函数均不动。

遮罩只存在于这个一次性合成代码中；没有制作可继续使用的独立毛发资产、做分割/抠图、增加毛纹或输出透明毛层。50/2/3参数沿用第一幕，不是另加大面积模糊去掩饰结果。

## 3. 实际视觉结果

已实看comparison-0.png的两侧200%肩部局部，并结合分析图核对来源。

- 原斜缝有一部分被盖住，但新的胸毛覆盖向前臂内伸，橙色前臂上部被削去，出现更低、更浅的覆盖边。局部看是身体像素压在臂面，不是腮毛自然垂下。
- x≈515刚性握笔分界左侧出现明显竖直台阶。排除手爪虽然保住爪/笔，反而暴露“干净身体带”和既有臂之间不兼容的交界。
- 肩部拼接感未得到整体明确改善；原缝的位置变化不算修复。失败发生在t=0，无须借后段压缩作否定理由。

checks.json：只测t=0，70%幅度；4393个像素改变，局部裁框外变化为0，完全不透明的握笔层像素变化为0。这些只证明操作范围，不能替代视觉评价。

## 4. 判定与后续边界

**stop-fur-route：第二幕毛发路线停止。** 不扩展到2.581秒、3.8秒，也不继续试新的补片、毛发生成、抠图、独立透明层或ORA制作。

原因是第一幕可复用的是合成机制，而其成功依赖的“按本姿态重画且准确注册的轮廓素材”在第二幕不存在。干净底图缺少腮臂分界；含正确接合视觉的扁平原画又混着旧臂。若要让相同机制成立，就需要新的兼容补绘素材，已满足用户指定的停止条件。不是断言所有绘画手段理论上都无效，而是在现有资产与本轮约束下不值得继续毛发方向投入。

接下来应转向**更保守的写字动作方案**：降低对肩根和臂面变化的需求，优先考虑保留可用静态姿态、只表达必要的书写意图，先用最小动作验证整体观感。70%仍只是既有研究基准，不因本报告自动接入正式动画。本轮不提出新轨迹参数、不实施动作优化，保留头部/书页等已确认范围。

inputs.json记录读取依赖的SHA-256。capture.mjs复用已有离线Chrome/CDP导出方式。源码与原始素材未覆盖，第一幕成品未改。历史实验与绘画模板保留作证据，但不再作为默认继续工作的毛发路线。
