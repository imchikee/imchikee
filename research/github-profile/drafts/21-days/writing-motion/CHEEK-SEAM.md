# 脸颊补片接缝修订

2026-11-04，用户截图红框指出“脸部似乎有点瑕疵”。红框为握笔手后方、脸颊左下方沿原笔杆方向出现的斜向色带，不是角色本身的面部结构。旧截图与原合成代码/数据/GIF/关键帧在`cheek-seam-rejected/`。

原因是v16去手笔背景与原图脸颊色调略有差异，原背景蒙版沿着旧笔杆只接入窄条，于是整行书写、手向左移动后露出楔形接缝；生成背景的脸颊/纸页交界还比原图低约3–6原画像素。原尺寸起笔和结束画面中均能辨认，不应把像素检查通过当作画面无瑕疵。

本轮只修`shot.js`的固定背景合成。沿用已有`clean-writing-background-v16.png`，将原笔杆后方的窄条扩为连续脸颊背景，外缘渐变落在x420–630、y710–890的局部区域；面部五官和轮廓不参与移动。对靠近纸页的补片取样逐渐向下偏5原画像素，以对齐脸颊下缘，避免再混出第二条横向边界。原手、笔、前臂蒙版及书写轨迹/时序不另改，仍逐笔写`++i;`，不重画角色，不调用生图/API/CLI。

已实际看正常整幅、原尺寸起笔/中段/完成、12格连续帧，以及`cheek-comparison-v17.png`左修前/右修后局部并排；原斜向楔形色带和下缘短横缝已不再出现。`cheek-comparison-v17.gif`是同一位置的动态对照。3.2秒96帧导出通过，起笔粉爪中心对应原图、文字底图窗口外RGB检查通过；选定60×80脸颊区域、纸页、静态代码、纸页上缘及装订区域在四帧保持不动。上述像素检查只保证各自选定区域的性质，不代替自然度评价。

第一幕和线上根目录README/assets未改，未发布。用户此轮只指出脸颊瑕疵，不代表对整行书写、造型或第二幕整体已确认。
